Built and working

The machine is in good shape

A single fleet surface at /ops/standing, phone-operable and repo-filtered, deriving every verdict from live row counts. A Ralph autonomous loop with single-flight control, attempt caps and a supervised-path merge boundary. 63 registered guardrails with severity semantics, proof-of-firing fixtures and a registry that fails closed. A PII gate on pre-commit, commit messages, every PR and weekly. A design system published to npm with a Figma sync foundation. Visual regression now gated on pull requests and on main.

That is a real platform. Measured against the scope test, it is also mostly indirect.

Two things worth naming

Structural, not incidental

15 of 90 open issues are actionable by an agent

Every open issue across the six repos was triaged with adversarial verification — a second agent tried to refute each verdict, and 27 of 33 first-pass close/do-now calls were overturned. The split below is what survived that.

The count rose from 76 to 90 on purpose: two epics (ops#238, site-engine#153) were decomposed into 15 children. Decomposition inflates the number before it deflates it — it converts un-startable epics into shippable units.

Three of the four big answers came in

These were the decisions with the largest downstream fan-out. Answered on 19 September:

  1. site-engine#203 — build it now, all five. #205, #206 and #207 shipped the same day; #208–#210 are unblocked and queued.
  2. ops#401 — ralph-auto is now conditional, not blanket. Tag it only on an issue whose definition of done names no supervised path. The blanket practice is what let PRs #368 and #362 merge lead-handling diffs unreviewed.
  3. Engine v1 released — advanced from f645031 to a4f0c21, re-vendored in all three callers and verified live. Ralph#23 fixes orphan-branch recovery to pick the newest branch; Ralph#24 makes the kit-drift check compare against the engine revision actually running.

Two safety constraints that must not be reordered

Ralph#25 before ops#402. The revenue-path boundary currently holds because risky issues simply aren't tagged ralph-auto — a human convention, not a mechanism. The ops#401 decision tightened that convention; it did not replace it. Flip auto-merge to default-on before the engine enforces paths and every green ralph/* PR self-merges, including one touching lib/leads/. Closing ops#238 in its stated order would delete the protection PR #375 added.

A new section variant is always an enum change, so it always needs the ops mirror (lib/schema + the vendored snapshot). A new optional field may not — se#84's analytics was safe only because its provider is a z.literal, and collectEnums() collects only kind === 'enum'.

Snapshot, not a living document. Regenerate it rather than patch it. For whether a pipeline stage actually works, read /ops/standing — a document that restates live state will drift, and this one will too.
