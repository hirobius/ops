1 — Why this exists

The fleet (Ralph loop + dispatched @claude issues + the lead-gen agent pipeline) runs a growing number of autonomous Claude sessions with zero cost/volume signal anywhere in /ops. Today the only way to know "how much are we burning" is to open GitHub Actions and eyeball run counts. docs/signal/SIGNAL.md FIX-014 flagged this in the old orchestration era as a LangSmith-style gap; the board-comb recycled it as this issue. This doc answers the three DoD questions — what's measured, where it surfaces, what feeds it — so Adrian can accept (or redirect) the shape before any of it gets built.

Same idiom as run-log.mjs/notify.mjs: pure appendBurn/readBurn functions, {path} override for tests, tolerant JSONL parsing, no Supabase migration, no new api/*.ts route (Hobby plan is already at 12/12 function slots per the 2026-07-12 digest ship — a burn API would need a fold, same constraint every new route hits now).

5 — Where it surfaces

/ops already has the right shelf: Fleet (events+run-log+alert-log merged timeline) sits above Runs. A new Codeburn panel slots next to them, same build-time import.meta.glob read as RunsPanel/FleetTimeline — no new API route needed for the read side.

TileData

Fleet sessions today, by reporun-log.jsonl count — volume, no $ sign anywhere on this tile

The two halves render as visually distinct tiles (a $ tile styled like existing cost UI, a volume tile styled like the existing Runs/Fleet count tiles) so nobody mistakes a session count for a dollar figure.

6 — Open questions for Adrian (blocks §7 build, not this spec)

Q1 — Is per-session $ tracking for fleet dispatch wanted at all, given it's flat-rate?

The Max subscription has no per-session dollar cost to show. The honest signal is volume/quota pressure. Confirm that's the right framing before a panel gets built that Adrian reads as "$" and isn't.

Q2 — Is telemetry/pod-runs.jsonl (Hermes/Ollama) still live, or dead weight from the pre-Ralph era?

If the local-model kanban isn't run anymore, FIX-019 (broken token counts) and this whole source can be dropped from scope rather than fixed.

Q3 — Does GitHub's Actions API expose enough to detect Max-plan rate-limit proximity (429s/backoff), or is that only visible from inside a running session's own transcript?

Unverified in this pass — needs a spike against a real Actions run before committing to that metric.

Q4 — Cost ceiling / alerting: wanted now, or observability-only first?

docs/ai/MODEL_TIERS.md already documents a ceiling-gate concept (costCeiling = projected × 1.25) from the Hermes era. Reasonable to resurrect for the metered-API half once burn.jsonl exists — but that's a second slice, not this one.

7 — Proposed build slices (smallest first, once accepted)

A

Capture usage at the source

lib/agent/llm.mjs returns {result, usage} instead of swallowing response.usage; callers in lib/agent/index.mjs pass a feature/ref tag; lib/ops/burn.mjs (new, mirrors run-log.mjs) appends to docs/ops/burn.jsonl. No UI yet — this slice just stops throwing the data away.

B

/ops Codeburn panel — metered $ half

Reads burn.jsonl at build time (same idiom as RunsPanel), renders the tiles in §5's first three rows. Ships once slice A has real data to render.

C

/ops Codeburn panel — fleet volume half

Reads existing run-log.jsonl + ralph/runs.jsonl — no new writer. Independent of A/B; can ship first if Q1 resolves toward "volume only, skip the $ half for now."

D

Cost ceiling / alerting (only if Q4 says yes)

Resurrect the Hermes-era ceiling-gate pattern against real burn.jsonl data; fan out through the existing lib/ops/notify.mjs seam (already has a blocked/deploy_error kind vocabulary to extend).

Per CLAUDE.md's dispatched-task discipline, these ship as separate sub-issues once Adrian accepts this spec — not bundled into one PR.

8 — Non-goals

  • Not attempting to invoice-reconcile against the actual Anthropic Console bill in this pass — MODEL_TIERS.md prices are an estimate, not a source of truth for accounting.
  • Not touching the Max-subscription billing/plan itself — this is read-only observability.
  • Not building the alerting/ceiling slice (D) without an explicit yes on Q4.
  • Still under the 2026-07-08 feature freeze — none of §7 ships until the freeze lifts or Adrian explicitly carves out an exception for this issue.
